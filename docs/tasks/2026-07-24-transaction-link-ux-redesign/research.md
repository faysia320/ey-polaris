# Research: 거래 묶음 UX 재설계 — 수정 모달 진입 + 병합 행 표시

- 날짜: 2026-07-24
- 요청 원문:
  > 묶음 기능을 개발했는데 아래 내용을 확인해서 개선안을 수립해줘
  > 1. 묶음 UI를 그리드 체크박스 방식으로 하지 말고 거래 수정 버튼을 눌렀을 때 뜨는 모달 footer 좌측 끝에 묶음 버튼을 만들고 그 버튼을 눌렀을 때 지금 보고 있는 거래내역과 연결할 거래내역을 선택할 수 있는 모달이 또 나와서 거기서 선택해서 서로 묶을 수 있도록 해줘.
  > 2. 묶인 건들은 하나의 건으로 합쳐져서 그리드상에 보여지면 좋겠어. 그리고 묶음 해제버튼이 묶음 보기 버튼으로 역할이 바뀌고 눌렀을때 묶인 각각의 내역이 어떤건지와 묶음 해제할수있는 기능을 거기서 제공했으면 좋겠어

## 요약
현재 묶음 기능은 (1) 그리드 좌측 체크박스로 2건을 선택 → 상단 액션 바의 "묶기" → 유형 확인 다이얼로그로 연결하고, (2) 묶인 두 건은 각각 별도 행으로 남은 채 "묶음 배지"와 "묶음 해제(Unlink)" 아이콘만 붙는다 (`TransactionsPage.tsx:283-408`, `571-609`, `751-770`). 요청은 이 두 축을 모두 바꾼다. **요청 1**: 선택 방식을 없애고 "거래 수정" 모달 footer 좌측 끝의 "묶음" 버튼 → 연결 대상 선택 모달 → 상대 거래 선택으로 진입시킨다. **요청 2**: 묶인 두 건을 그리드에서 한 행으로 합쳐 보여주고, "묶음 해제" 버튼을 "묶음 보기"로 바꿔 그 안에서 각 다리 확인·해제를 제공한다.

묶기/해제의 서버 계약(`POST/DELETE /transactions/link`)과 통계 상쇄(analytics의 `link_type` 기반 처리)는 **그대로 유지**된다 — 이번 작업은 대부분 프론트 표시·상호작용 재구성이다. 다만 병합 행을 안정적으로 렌더링하려면(환불 순지출, 이체 출금→입금 계정) 파트너 다리 정보가 필요한데, "전체 기간" 뷰에서 서로 다른 달의 두 건이 묶일 수 있어(기존 데이터 포함) 파트너가 현재 필터 목록에 없을 수 있다. 따라서 거래 목록 응답(`TransactionOut`)에 **파트너 다리 요약을 임베드**하는 것이 유일한 백엔드 변경이다.

## 영향도
- **analytics/대시보드**: 변경 없음. 묶기/해제는 `link_id`·`TransactionLink`만 조작하고 집계는 `link_type`을 이미 읽는다. 병합은 표시 계층 한정 → 통계·잔액·자산 추이 불변.
- **캘린더 월별 합계**: 불변(`TransactionCalendar.tsx:29-40`은 개별 leg 기준). 일별 상세 목록만 병합 표시로 바뀐다.
- **정렬/페이지네이션(TanStack Table)**: `data`가 `Transaction[]`에서 "표시 행"(개별 거래 | 병합 묶음) 배열로 바뀌므로, `accessorKey('date'|'amount')` 컬럼을 `accessorFn` 기반으로 전환해야 한다. 페이지 크기·정렬 UX는 유지.
- **기존 묶음 데이터**: 그대로 병합 표시로 렌더된다. "전체 기간" 뷰에서 만들어진 교차-월 묶음도 파트너 임베드 덕분에 단일 leg만 로드돼도 병합 행으로 표시 가능.
- **모바일 카드/캘린더 일별 목록**: 표와 동일한 표시 행 데이터를 공유하도록 병합을 공통 파생값으로 계산(일관성).

## 성공 기준 (Acceptance Criteria)
- [ ] AC-1: "거래 수정" 모달을 열면 footer 좌측 끝에 "묶음" 버튼이 있고, "거래 추가"(신규) 모달에는 없다 — /qa에서 브라우저로 두 모달을 열어 확인.
- [ ] AC-2: 이미 묶인 거래의 수정 모달에서는 "묶음" 버튼이 없거나 비활성이고, 대신 "이미 묶임"류 안내가 보인다 — 묶인 거래를 (묶음 보기→수정 경로로) 열어 확인.
- [ ] AC-3: 수정 모달의 "묶음" 버튼 클릭 시 "연결 대상 선택" 모달이 열리고, **현재 조회 목록** 중 반대 구분(수정 대상이 지출이면 수입, 수입이면 지출)이며 아직 묶이지 않은, 자기 자신이 아닌 거래만 후보로 나열된다 — 후보 목록의 구분/상태를 눈으로 확인.

## 결정 사항 및 출처
- [사용자 확인] 연결 대상 선택 모달의 후보 범위 → **현재 조회 목록만**: 지금 화면에 로드된 반대 구분 거래만 후보로 노출한다. 별도 후보 검색 백엔드 엔드포인트는 만들지 않는다. 다른 달 건을 묶으려면 해당 월/전체 기간으로 필터를 이동한다.
- [사용자 확인] 병합 행의 개별 다리 수정 → **묶음 해제 후 수정**: "묶음 보기" 모달은 확인·해제만 제공하고, 각 건 수정은 해제하여 개별 행으로 되돌린 뒤 기존 수정 모달로 한다. 이에 따라 묶인 거래의 수정 모달에는 "묶음" 버튼을 노출하지 않는다.
- [기술 결정] 파트너 다리 요약을 `TransactionOut`에 임베드: 병합 행 렌더(환불 순지출·이체 출금→입금)와 묶음 보기 모달이 파트너가 현재 필터 목록에 없어도 동작하도록. 필드명·정확한 구성은 구현 재량이되 프론트/백엔드 키를 일치시킨다.
- [기술 결정] 서버 묶기/해제 계약(`POST/DELETE /transactions/link`)과 analytics 집계는 변경하지 않는다 — 이번 작업은 표시·진입 UX 재구성에 한정.
- [기술 결정] 병합·묶음 보기 표시는 표·모바일 카드·캘린더 일별 목록에 **일관 적용**한다(모바일 퍼스트 제약, 같은 논리 표시 행 공유).
- [기술 결정] 병합 앵커 규칙: `link_id`당 1행. 양다리 로드 시 지출 leg 앵커, 한쪽만 로드 시 로드된 leg 앵커.
