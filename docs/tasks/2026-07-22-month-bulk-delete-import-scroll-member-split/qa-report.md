## 검증 시나리오

**환경 정합성 (중요)**
- 기동 중이던 `docker compose` 백엔드 컨테이너가 **현재 작업 트리와 불일치**함을 발견했다. 컨테이너 내부 `transactions.py`에는 구버전 **2단계 삭제**(`select id` → `delete where id IN`) 코드가 들어 있었고, 현재 트리의 **단일 쿼리**(`delete().where(*conditions)`)가 아니었다(`docker compose exec backend grep` 로 확인, 볼륨 마운트 없음).
  - → `docker compose up -d --build backend`로 재빌드 후 `grep -c 'bind 파라미터' = 1`로 트리 일치를 확인하고 **모든 백엔드 검증을 재빌드 이후에 수행**했다.
  - → 결과적으로 1회차 보고서의 "Low-6 단일 쿼리로 단순화하고 `major` EXISTS까지 정상 처리됨을 실측" 이라는 주장은 **그 코드가 올라가 있지 않은 백엔드를 대상으로 한 것**이었다. 이번 회차에서 내가 직접 재검증했다(아래).
- 프론트는 `:3000` 컨테이너가 2주 전 이미지라 사용하지 않고, 현재 트리를 서빙하는 `npm run dev`(127.0.0.1:5199)를 재사용했다. 재사용 전 `/src/pages/TransactionsPage.tsx`에 `bulkDeleteError`, `/src/pages/AssetsPage.tsx`에 `splitMembers`가 포함되는지 확인해 트리 일치를 검증했다.
